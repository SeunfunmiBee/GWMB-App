# Porting ledger: Supabase server logic → Worker

Generated by `api/scripts/ledger.py` from the final Supabase schema. Each item below must exist in the Worker
(with a test) before the matching app code moves off Supabase in Phase 3. Read the SQL body in the listed migration.

## 1. Schema rules D1 cannot enforce

- `mentorship_sessions.notification_channels` ⊆ {in_app, push, email}: validate on write.
- `mentorship_sessions.distribution_surfaces` ⊆ {mentorship, learn, home, related_courses}: validate on write.
- `chapter_admins.created_by`, `local_activities.created_by`: set to the caller's user id (was `auth.uid()` default).
- `marketplace_inventory.career_areas` / `readiness_gaps`: GIN indexes dropped; filter JSON arrays in the Worker.
- `membership_records`: the normalized identifier/email lookup index used SQL functions; store normalized values from the Worker.
- Scheduled job `gwmb-notification-dispatch` (pg_cron, every minute) becomes a Worker Cron Trigger.
